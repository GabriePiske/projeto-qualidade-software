# Modelos de Maturidade – LocalEats

**Equipe:** Tech Quality

**Integrante:** Gabriel Piske

**Sistema:** Local Eats (https://local-eats-unisenac.vercel.app/static/index.html)

---

## 1. Diagnóstico de Maturidade

| Critério | Avaliação |
|-----------|-----------|
| Os requisitos são documentados? | Parcial |
| Existe controle de mudanças? | Parcial |
| Há atividades de teste definidas? | Sim |
| Os defeitos são registrados? | Parcial |
| O processo de desenvolvimento é conhecido por toda a equipe? | Sim |
| As tarefas são planejadas e acompanhadas regularmente? | Parcial |
| Existe padronização para implementação de funcionalidades? | Parcial |
| Os testes são executados antes da entrega das funcionalidades? | Sim |
| Há revisão de código ou validação por outro integrante da equipe? | Parcial |
| A equipe utiliza ferramentas para gerenciamento das atividades? | Sim |
| Os artefatos do projeto (requisitos, testes, código) são organizados e versionados? | Sim |
| Existe rastreabilidade entre requisitos e funcionalidades implementadas? | Parcial |
| A equipe realiza reuniões ou momentos de retrospectiva para identificar melhorias? | Parcial |
| Existem indicadores ou métricas para acompanhar a qualidade do projeto? | Não |

### Classificação do Processo

**Nível de Maturidade: Gerenciado**

### Justificativa

O processo da equipe apresenta práticas básicas de gerenciamento, como planejamento das atividades, controle de versão e execução de testes. Entretanto, ainda existem limitações relacionadas à documentação, rastreabilidade, métricas de qualidade e padronização completa dos processos. Dessa forma, o projeto demonstra características compatíveis com um processo gerenciado, mas ainda não possui maturidade suficiente para ser considerado um processo definido ou quantitativamente gerenciado.

---

## 2. Lacunas Identificadas

| Lacuna | Impacto |
|---------|---------|
| Ausência de métricas de qualidade | Dificulta o acompanhamento da evolução do projeto |
| Documentação incompleta dos requisitos | Pode gerar erros de entendimento e retrabalho |
| Falta de rastreabilidade entre requisitos e funcionalidades | Dificulta identificar a origem de problemas e validar entregas |
| Revisão de código não realizada de forma padronizada | Possibilidade de defeitos chegarem à produção |
| Processo de retrospectiva pouco estruturado | Reduz oportunidades de melhoria contínua |

---

## 3. Propostas de Melhoria

| Melhoria | Benefício |
|-----------|-----------|
| Definir métricas de qualidade (bugs, cobertura de testes, tempo de correção) | Melhor acompanhamento da qualidade do projeto |
| Padronizar a documentação dos requisitos | Redução de ambiguidades e retrabalho |
| Implementar rastreabilidade entre requisitos, testes e funcionalidades | Maior controle sobre as entregas |
| Adotar revisão de código obrigatória antes das entregas | Redução de defeitos e melhoria da qualidade do código |
| Realizar retrospectivas periódicas da equipe | Identificação contínua de melhorias no processo |

---

## Conclusão

A equipe compreendeu que a maturidade de processos está diretamente relacionada à capacidade de produzir software com qualidade de forma consistente. Embora o LocalEats já possua práticas básicas de gerenciamento e testes, ainda existem oportunidades de melhoria relacionadas à documentação, métricas, rastreabilidade e revisão de código. A adoção dessas melhorias pode elevar o nível de maturidade do processo e contribuir para entregas mais confiáveis e eficientes.
